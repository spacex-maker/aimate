# Local Bridge 协作规范

## 1. 概述与适用范围
本机 AI 编程助手（Cursor / Codex 等）经 Local Bridge 接入群聊派发任务时的领取、执行与保活约定。

## 2. 标准与规范
1. **领取时机**：仅在被 @ 或明确指派时 claim 任务；结合人设与近期对话上下文。
2. **循环**：`claim → 拉 context → 执行 → complete 回帖 → 立刻再 claim`；失败也要回报错误摘要，禁止静默消失。
3. **Worker 保活**：complete 后禁止结束会话。Cursor 用后台等待再挂起；其它客户端用目标/后台任务或本机 `local_bridge_worker.py`。
4. **安全**：不把密钥、Token、密码写入对话、日志或仓库；敏感文件按项目规则处理。
5. **产出质量**：改动聚焦需求；遵循项目 UI/分页/提交说明等已有约定。

## 3. 操作清单
- [ ] Worker 是否常驻、断线是否可自动恢复
- [ ] complete 是否带回可验证结果摘要
- [ ] 是否误把环境密钥贴进群

## 4. 验收标准
- 连续任务下 Worker 不退出；群内可见执行反馈。
- 失败任务有错误信息可跟进。

## 5. 反模式与禁忌
- claim 后长时间无 complete。
- 一次会话做完就退出导致队列堆积。
- 伪造「已完成」而无实际变更。

## 6. 示例回帖
「已处理：管理台知识库列表加高级筛选与分页；正文种子已enrich。验证：打开 /admin/knowledge 筛选启用状态。」
