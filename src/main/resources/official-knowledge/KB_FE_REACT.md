# 前端 React 工程约定

## 1. 概述与适用范围
适用于管理台与用户控制台的 React + TypeScript 页面。原则：**页面管数据、组件管展示、请求走统一客户端、交互状态可预期**。

## 2. 标准与规范
1. **分层**：路由页/容器负责拉取与 mutation；展示组件尽量无副作用，通过 props 驱动。
2. **数据获取**：列表必须服务端分页；筛选变更重置到第 0 页；加载态与空态分开，禁止把「加载中」写成「暂无数据」。
3. **下拉框**：统一使用项目 `AppSelect` / `AdminSelect`，禁止原生 `<select>`。
4. **表单**：校验错误贴近字段；提交中禁用按钮；成功/失败用 toast 给出人类可读文案。
5. **样式**：遵循现有 admin/user 设计变量与布局组件；不引入与系统冲突的全局样式。
6. **可访问性**：按钮有明确文案；弹层可关闭；焦点不被困死。

## 3. 操作清单
- [ ] 新列表是否接 `{ items, page, size, total, totalPages }`
- [ ] 是否有 `AdminPager`（或等价）分页条
- [ ] 高级筛选字段是否齐全：关键词 + 状态/角色/关联 + 时间等（按业务）
- [ ] 错误是否被吞掉；失败是否提示
- [ ] 是否误用原生 select / findAll 全量数据

## 4. 验收标准
- 慢网下可见加载；零数据时空态明确。
- 筛选组合切换后页码回到 0，结果与筛选项一致。
- 键盘可操作主要按钮与关闭弹层。

## 5. 反模式与禁忌
- 前端一次拉全表再 `slice` 分页。
- 用 `any` 绕过类型，或把 API 错误直接 `console.log` 了事。
- 在渲染函数里发起无防抖的请求造成风暴。

## 6. 示例
```tsx
// 筛选变更时重置页码
onChange={(v) => { setEnabled(v); setPage(0) }}
```
