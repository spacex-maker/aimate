# 线上稳定性与值班手册

## 1. 概述与适用范围
覆盖生产事故分级、响应、回滚、沟通与复盘。适用于 on-call、发布值班与核心链路负责人。

## 2. 标准与规范
1. **分级**  
   - P0：全站或核心交易/登录不可用，或数据损坏风险 → 立即止损（回滚/开关）并拉通。  
   - P1：核心链路显著降级（错误率/延迟超阈）→ 限流/降级 + 根因排查并行。  
   - P2：非核心功能异常 → 工作时间处理，记入缺陷队列。
2. **变更原则**：任何上线必须可回滚；灰度/开关优先于硬切。
3. **沟通**：P0/P1 建立事故频道：现象、影响面、当前动作、下一次同步时间。禁止只在私聊处理。
4. **观测**：先看黄金指标（流量、错误、延迟、饱和度），再下钻日志/Trace；保留时间线。
5. **复盘**：24–72 小时内完成；写清时间线、根因、影响、改进项（负责人 + 截止日期）。

## 3. 操作清单
- [ ] 确认影响面与分级
- [ ] 止损（回滚 / 开关 / 扩容 / 限流）
- [ ] 同步干系人与状态页（如有）
- [ ] 根因定位与验证
- [ ] 复盘与改进项入库

## 4. 验收标准
- P0 从发现到止损有明确时限目标（团队约定，如 15 分钟内进入止损动作）。
- 复盘改进项可追踪，到期未完成会升级。

## 5. 反模式与禁忌
- 未止损先「深入改代码」。
- 无回滚方案的热修直接上生产。
- 复盘归咎个人而无系统改进。

## 6. 示例时间线模板
`T0 发现 → T1 分级/拉通 → T2 止损生效 → T3 影响确认 → T4 根因假设 → T5 修复验证 → T6 复盘`
