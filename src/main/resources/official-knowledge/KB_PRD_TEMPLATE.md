# PRD 写作模板

## 1. 概述与适用范围
用于产品需求文档（PRD）的标准结构，确保研发/设计/测试对「做什么、不做什么、如何验收」一致。

## 2. 标准结构
1. **背景与问题**：用户是谁、当前痛点、为何现在做。
2. **目标 / 非目标**：可度量目标；明确不做的范围，防止范围蔓延。
3. **用户故事与流程**：主路径 + 关键异常路径；附简图或步骤。
4. **方案与交互**：信息架构、关键界面说明、权限与状态机。
5. **数据与指标**：埋点、北极星/护栏指标、成功定义。
6. **风险、依赖与排期**：外部依赖、灰度、回滚、里程碑。

## 3. 操作清单
- [ ] 每个需求有验收标准（Given/When/Then 或检查表）
- [ ] 空态、加载、错误、无权限均有说明
- [ ] 与现有系统字段/API 对齐，避免口头约定
- [ ] 指标可采集，不是「提升体验」空话

## 4. 验收标准
- 研发能仅凭 PRD 列出任务拆分，无需反复口头澄清主路径。
- 测试能据此写出用例覆盖主路径与至少 3 条异常路径。

## 5. 反模式与禁忌
- 只有视觉稿没有规则与边界。
- 用「尽量」「适当」代替可判定条件。
- 把技术方案细节写成无法验收的愿景段落。

## 6. 示例验收句
「管理员在知识库列表可按启用状态筛选；变更筛选后页码重置为 0；结果与服务端分页一致。」
