# Java 服务端 API 设计规范

## 1. 概述与适用范围
本规范适用于 Spring Boot / 同类 Java 服务对外暴露的 HTTP API（含管理端与用户端）。目标是：**可机读、可演进、可观测、安全默认**。不覆盖消息队列、gRPC 内部契约（可参考同等原则）。

## 2. 标准与规范
1. **资源路径**：用名词复数表达资源（`/api/orders`），动作用 HTTP 动词；避免 `/doCreateOrder` 式 RPC 路径。
2. **列表分页**：默认 `page=0&size=20`，`size` 上限 100；响应固定形状 `{ items, page, size, total, totalPages }`。禁止一次拉全表再前端切页。
3. **错误体**：失败返回可机读字段（如 `error` / `message` / 可选 `errorCode`）；对客户端展示人类可读文案，日志保留完整堆栈与请求 ID。
4. **幂等**：写操作（尤其支付、招聘、扣费）支持幂等键（Header 或业务单号）；重试不得产生重复副作用。
5. **认证授权**：对外 Bearer / Session 明确约定；管理端与用户端权限隔离。禁止在日志、响应、仓库中打印密钥与 Token。
6. **兼容性**：新增字段可选；废弃字段至少保留一个大版本并文档标注；破坏性变更走版本前缀或并行端点。
7. **校验**：入参在边界层校验（Bean Validation）；非法请求 400，未登录 401，无权限 403，不存在 404。

## 3. 操作清单
- [ ] 新接口是否有 OpenAPI/注释说明：鉴权、分页、错误码、示例
- [ ] 列表是否服务端分页且响应形状统一
- [ ] 写接口是否具备幂等与并发控制（乐观锁/唯一约束）
- [ ] 敏感字段是否脱敏；审计日志是否记录操作者与对象 ID
- [ ] 超时、重试、限流策略是否与网关/客户端一致

## 4. 验收标准
- 用错误 Token / 无权限账号调用时，行为符合 401/403，无数据泄露。
- 连续两次相同幂等写请求，业务结果只生效一次。
- 分页在边界页（空页、最后一页、size=1）表现正确。

## 5. 反模式与禁忌
- 用 200 + `{ success:false }` 掩盖 HTTP 语义（除非历史兼容且已文档化）。
- 在路径或 Query 中传递密钥。
- 返回整表实体图导致 N+1 与过度暴露内部字段。
- 无版本策略的随意改字段类型。

## 6. 示例
```http
GET /api/admin/knowledge/bases?page=0&size=20&enabled=true
Authorization: Bearer <token>
```
成功：`{ "items": [...], "page": 0, "size": 20, "total": 42, "totalPages": 3 }`
